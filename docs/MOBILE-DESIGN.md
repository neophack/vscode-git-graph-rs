# 手机布局设计说明

| 项 | 内容 |
|---|---|
| 设置项 | `git-graph-rs.mobileAdaptation`（默认关闭；在设置面板“全局设置”中也可切换） |
| 切换条件 | 设置开启 **且** 视图宽度 ≤ 600px；宽度未知（后台标签页，宽为 0）时保持宽布局 |
| 设计依据 | `mobile-app-design` skill（awesome-skills/mobile-app-design，MIT）：触控目标、字号、对比度、无 hover、安全区 |
| 实现位置 | `web/main.ts`（布局判定、行高、两行式行）、`web/styles/mobile.css`（全部样式）、`web/observers.ts`（长按）、`web/commitDetailsView.ts`（全屏详情）、`web/contextMenu.ts`（底部操作菜单） |

## 1. 切换机制

- 每次渲染开始时，`renderTable` 调用 `applyNarrowWindowLayout(isNarrowWindow())` 判定布局。这一次的结果记在 `renderedNarrowWindow` 中，之后一切以它为准：行高、提交详情的停靠方式、长按是否生效。“DOM 里实际是什么”和“代码认为是什么”因此始终一致。
- 窗口缩放时，若跨越 600px 断点，resize 观察器会调用 `updateNarrowWindowLayout()` 重新渲染。如果此时提交详情是以内联方式打开的，会先把它关闭，因为两种布局下详情面板的 DOM 结构不同。
- 进入手机布局时，`<body>` 加上 `mobileMode` 类（同时保留旧的 `narrowWindow` 类以兼容）。所有手机端样式都限定在 `body.mobileMode` 之下，宽布局完全不受影响。

## 2. 界面设计（扁平、紧凑，参照 iOS / Material 3）

整体语言：无边框，靠填充色和 0.5px 发丝线分层；胶囊控件；所有颜色从 VS Code 主题变量派生（`color-mix`），深色、浅色、高对比度主题通用。

### 2.1 顶栏：单行 52px 应用栏

```
┌──────────────────────────────────────────┐
│ ( ⑂ main ▾              )  🔍  ⟳  ⋯     │
└──────────────────────────────────────────┘
```

- 仓库/分支下拉是 36px 高的胶囊：前置图标 + 加粗名称 + 右侧 chevron（展开时旋转）。多仓库时仓库胶囊最多占 38% 宽。
- 栏内只保留 **查找、刷新、⋯**，均为 44px 圆形触控目标。其余功能（定位 HEAD、拉取、路径过滤、统计、终端、设置、显示远程分支）收入 **⋯ 底部菜单**；“显示远程分支”是开关。路径过滤启用时，其图标留在栏内作为状态指示。
- 顶栏吸顶，带毛玻璃（`backdrop-filter`），列表从下方滚过。
- 下拉菜单是悬浮圆角卡片（14px 圆角，阴影），选项 44px，选中项为强调色 + 对勾。

### 2.2 提交列表：52px 双行

```
│ ●  修复登录超时                      16:32 │  第 1 行：标题 + 紧凑日期
│ │  [⑂ main|origin] 张三         a1b2c3d4 │  第 2 行：引用标签 · 作者 · 短哈希
```

- 日期像邮件列表：今天显示时间、昨天、一周内显示星期、其余显示 “Oct 9”（跨年带年份）。完整日期在 tooltip。
- 引用标签从标题行移到第二行，标题不再被挤掉。标签是扁平色块，用该提交的泳道颜色着色；当前分支为实心。
- 行间是缩进到文字的发丝线（`box-shadow`，不占行高）。列标题行折叠为 0 高（其图形格仍决定图形列宽）。
- 行高 `MOBILE_ROW_HEIGHT = 52`，所有窗口化渲染（占位行、视口锚点）经 `getRowHeight()`，因此长列表依然精确。

### 2.3 超长历史（上万条提交）

- 窗口化渲染：任何时刻 DOM 里只有视口附近约 40 行；10,000 条提交在 Chrome 中加载约 1 秒，200 步跨全程滚动每帧约 16.7ms（60fps）。
- **快速滚动条**（`observeFastScroller`）：列表超过 6 屏时，滚动中右缘出现滑块；拖动它把位置直接映射到整个滚动范围，旁边的气泡显示顶部提交的日期和 “第 N / 总数 条”。1.5 秒后淡出。长按滑块不触发上下文菜单。

### 2.4 提交详情：全屏面板

- 52px 标题栏：关闭 · 短哈希 · 查找/更多操作。
- 摘要像一封邮件：标题（提交主题，20px）→ 署名行（圆形头像/姓名首字母、作者、日期）→ 正文 → 圆角分组卡片（提交、父提交芯片、作者、提交者）。父提交可点击跳转。
- “N 个文件变更  +A −D”分区头，右侧是列表/树分段控件与折叠/展开按钮（从标题栏移到这里）。行数统计到达后原地更新。
- 文件行 44px：着色字母徽标（A/M/D/R/U）+ 文件名 + 绿 +N / 红 −N。手机上不再常驻复制/打开图标，这些操作在长按菜单中。

### 2.5 右键菜单 → 底部操作菜单

- 触屏没有右键，**长按**（500ms，移动 ≤10px）派发 `contextmenu`，所有现有菜单无需改动。Android 自带 `contextmenu` 与计时器谁先到以谁为准；iOS 由计时器负责；菜单弹出后松手产生的 click 会被取消。
- 菜单是全屏遮罩 + 底部浮动圆角面板（距边 8px，iOS 风格）；以分隔符为界的每组是独立的圆角卡片。⋯ 菜单的条目带前置图标。
- 菜单挂在 `<body>` 上：`#view` 为 `position:fixed`，会形成独立层叠上下文，挂在里面盖不过详情面板。

### 2.6 对话框、查找栏与各面板

- 对话框：宽 `100vw - 32px`（最大 420px），16px 圆角；输入框填充色无边框；按钮纵向全宽 44px，主按钮用强调色。
- 输入框字号统一 16px（避免 iOS 聚焦缩放）。
- 查找栏：横跨整屏，从顶部滑入；设置、Reflog、统计、工作树面板全屏显示，关闭按钮为圆形。

### 2.7 适配的屏幕尺寸

390×844、360×780、430×932 已实测；≥428px 字号略增；<360px 隐藏第二行的哈希、收紧间距。无横向滚动（`scrollWidth` 等于视口宽）。

## 3. 设计规范对照（mobile-app-design）

| 规范 | 要求 | 本实现 |
|---|---|---|
| 触控目标 | iOS ≥ 44pt，Android ≥ 48dp | 按钮、下拉、菜单项 44–58px；提交行 52px。在 390px 视口下实测，没有小于 44px 的按钮 |
| 目标间距 | ≥ 8px | 通过 `--gg-mobile-gap: 8px` 统一 |
| 字号 | 正文 ≥ 16，绝对下限 14；标注 ≥ 11–12 | 标题 15px，元信息 12px，输入框 16px |
| 无 hover | 使用按下态 | 所有可点元素都有 `:active` 背景；悬停才显示的内容改为常驻 |
| 安全区 | 避开刘海和 Home 指示条 | 页面声明 `viewport-fit=cover`；所有贴边的固定元素都使用 `env(safe-area-inset-*)` |
| 长按菜单 | 平台标准的上下文操作方式 | 长按（500ms）弹出底部操作菜单 |
| 对比度 | 文本 ≥ 4.5:1 | 沿用 VS Code 主题变量，深色和浅色主题均已截图核对 |
| 无横向滚动 | — | 390px 视口下 `scrollWidth` 为 390 |

## 4. 验证

- **自动化**：`tests/webviewMobileAdaptation.test.mjs` 共 11 个用例，覆盖：
  - 设置关闭时不变化
  - 隐藏列与恢复列
  - 设置面板中的开关
  - 两行式行与 52px 行高（含虚拟滚动占位行）、宽布局恢复
  - 全屏详情面板与“更多操作”菜单、点遮罩关闭
  - 长按打开菜单并取消随后的点击
  - 滑动不触发长按
  - 宽布局下长按无效
- **真实浏览器**：`tests/browserRepro` 新增 `?cfg=mobile` 变体。在 Chrome 中以 390×844、触屏仿真截图核对了以下画面（深色和浅色主题）：
  - 提交列表、分支下拉、全屏详情
  - “更多操作”打开的底部菜单
  - 通过真实触摸事件长按引用标签弹出的菜单
  - 查找栏
- **全量回归**：Node 测试 706 个、真实浏览器布局检查 124 项全部通过。

## 5. 已知限制

- 断点固定为 600px，不可配置。
- 提交详情面板不支持下滑关闭手势，需要用左上角的关闭按钮。
- 不支持下拉刷新，需要使用工具栏的刷新按钮。
- 复现页的模拟宿主不响应 `loadConfig`，所以设置面板的内容只能在真实 VS Code 中核对。
